# GAEO.ru: единые элементы дизайна (Astro)

Дата: 27 октября 2026 года. Статус: внедрение поэтапно, без массовой переделки всех исторических страниц.

## Эталон

Главная GAEO.ru определяет стиль FAQ: `.faq > details.faq-item > summary.faq-q`, знак `+` в `.faq-toggle` и ответ `.faq-a`. Основные цвета, типографика, разделители, кнопки и отступы задаются существующими `public/assets/style.css` и `public/assets/internal.css`.

Для новых страниц услуг согласован светлый блок заявки без цветной плашки. Его текст и кнопка берутся из **уже существующего** `templates/partials/hub-cta-ru.html` / `hub-cta-en.html`. Кнопка открывает штатную форму через `/#lead` или `/en/#lead`. Не придумывать отдельные стили CTA и не добавлять обещаний результатов.

## Канонические компоненты

| Компонент | Назначение | Источник содержания |
|---|---|---|
| `src/components/design/FAQAccordion.astro` | Единый HTML FAQ (главная, новые кейсы, страницы услуг, отраслевые Astro-посадочные) | `FAQPage.mainEntity` в JSON-LD страницы либо `page.faq` у отраслевых посадочных |
| `src/components/design/LightLead.astro` | Согласованный светлый завершающий блок с 1 кнопкой | Общие `templates/partials/hub-cta-*.html` |
| `src/components/design/ApprovedCards.astro` | Сетки услуг, сценариев, этапов и ссылок на кейсы | `src/data/approved-design-content.mjs` |
| `src/components/design/ApprovedDesignSlot.astro` | Выбор шаблона для HTML-источников гибридного сайта | Маркер в странице, общий компонент и данные |
| `src/lib/approved-design-system.mjs` | Чтение утвержденных данных и строгая проверка полноты | JSON-LD, шаблоны CTA, файл данных |

Содержание страницы не копируется в разметку FAQ. **Единственный источник вопросов и ответов** для гибридных страниц с общим FAQ: ее собственный блок `FAQPage` в Schema.org. Изменение FAQ в JSON-LD автоматически меняет видимый ответ. Данные для карточек отдельно хранятся в `approved-design-content.mjs`, а их разметку определяет компонент.

Отраслевые посадочные, построенные из `IndustryCommercialLanding.astro`, используют тот же `FAQAccordion.astro` со своими отраслевыми вопросами. Бизнес-факты и содержание отраслей менять без проверки нельзя.

## Как добавлять блок на новой странице

Страницы сайта продолжают находиться в `src/legacy/pages/`. Вместо ручного HTML нужно поставить в нужное место маркер:

```html
<section class="site-service__section" id="faq">
  <div class="eyebrow">FAQ</div>
  <h2>Вопросы по теме</h2>
  <!-- GAEO_DESIGN:FAQ -->
</section>
<!-- GAEO_DESIGN:CONTACT -->
<!-- GAEO_DESIGN:SERVICES -->
<!-- GAEO_DESIGN:WHEN -->
<!-- GAEO_DESIGN:STEPS -->
<!-- GAEO_DESIGN:CASES -->
```

Это примеры **отдельных доступных компонентов**: использовать на странице только подходящие по смыслу. Для `FAQ` нужен полноценный `FAQPage` в Schema.org, для карточек нужен соответствующий раздел данных в `approved-design-content.mjs`. Если данные отсутствуют, сборка завершается ошибкой; дизайн нельзя незаметно подменить самодельным HTML.

Доступные виды карточек:

- `SERVICES`: название услуги, описание, перечень действий и кнопка.
- `WHEN`: примеры задач, заголовок и короткий текст.
- `STEPS`: порядок работ, заголовок и пояснение.
- `CASES`: ссылки на опубликованные кейсы, название и описание.

Для нового визуального варианта сначала согласовать назначение, затем добавить один общий компонент и автоматическую проверку. Избегать отдельных стилей `page-specific-cta`, `site-service__cta`, `site-service__faq` и повторения существующих FAQ вручную.

## Какие страницы уже используют общие компоненты

- Главная RU/EN: FAQ.
- 3 новых кейса разработки сайтов, каждый RU/EN: FAQ (всего 6).
- Разработка сайтов RU/EN: FAQ, светлый CTA, сетка ситуаций, этапы работ, ссылки на 3 кейса.
- Каталог услуг RU/EN: 2 карточки услуг и светлый CTA.
- Коммерческие отраслевые посадочные, генерируемые `IndustryCommercialLanding.astro`: общий FAQ.

**Другие исторические HTML-страницы пока не все перенесены.** Их список фиксируется в `src/data/preexisting-legacy-routes.mjs` как переходное исключение. Это не разрешение создавать новые копии нестандартных блоков. Перенос остальных старых типов страниц выполняется по частям, с сохранением URL, контента, визуального поведения и SEO.

## Как действует защита от случайного расхождения

1. `npm run build`: Astro генерирует общую разметку. Отсутствие вопросов, шаблона или данных блокирует сборку.
2. `npm run check:parity`: сохраняет точность HTML, кроме явно обозначенных общих блоков; только они заменяются компонентами.
3. `npm run check:design`: проверяет маркеры, FAQ/JSON-LD, текст кнопок, ссылки, количество карточек, отсутствие повторного HTML и запрещает новые страницы со скопированными блоками.
4. `scripts/qa_development_cases.mjs`, `scripts/qa_site_development_service.mjs` и отраслевой Playwright-тест проверяют ссылки, FAQ и мобильное отображение.
5. PR в `astro-source` и production workflow **оба** исполняют проверку дизайн-системы. Публиковать, минуя эти шаги, нельзя.

## Публикация

Код и данные меняются в рабочей ветке на основе `astro-source` → PR → успешная сборка и QA → слияние в `astro-source` → автоматическая проверенная публикация в `main` и GitHub Pages. Не редактировать итоговый `main` вручную. При неудачной проверке оставить PR открытым и исправлять причину.

## Дальнейшая миграция

После этой группы переносить шаблоны исторических статей, стратегий и других кейсов небольшими пакетами. До переноса проанализировать реальные различия: неодинаковые вопросы, юридические тексты, таблицы или специализированные виды карточек могут требовать собственного общего шаблона. Массовое приведение всего сайта к одной визуальной форме без учета функции блока недопустимо.
