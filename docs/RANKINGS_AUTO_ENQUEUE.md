# GAEO: автоматическое пополнение очереди рейтингов

Статус: **включено с 14.11.2026**. Исполнитель: задача ChatGPT Automations [GAEO: автопополнение рейтингов](https://chatgpt.com/), ID `6af82424e88c8191864cddc55b30523c`. Проверка **раз в час**, часовой пояс `Europe/Moscow`. Это плановая итерационная проверка, а не мгновенный webhook. Владелец — Алексей. Факт включения задачи подтвержден действием Automations API; результат будущих итераций проверяется отдельно.

## Назначение

Подхватывать новые **уже опубликованные** семьи рейтингов из единого реестра и атомарно включать их в существующую очередь `rankings-staging` без дубликатов. Один `ID темы` — одно задание. Исходные исследования IndexResearch и редакции других площадок входят в одно семейство, даже при различии заголовков, языков и методики.

Это автопополнение **очереди**, не автоматическая публикация. Подготовка текста RU/EN, изображения, контроль и общий выпуск остаются отдельными действиями штатного исполнителя/координатора.

## Источники

- [Единый реестр GAEO](https://docs.google.com/spreadsheets/d/1Hs3Z4BL1GyNcjgDYA35kU2YZDnmNEjq-MzDLqCPwKZo/edit), листы `Темы`, `Публикации`, при необходимости `Ссылки` и `Изображения статей`. Получать их через подключенный Google Sheets с актуальными метаданными и фактическим заполненным диапазоном, без зашитой последней строки.
- Текущие `rankings-staging/docs/rankings/queue.json`, `docs/rankings/excluded.json`, `docs/rankings/sources/<id>.json`.
- Детерминированный алгоритм выявления кандидатов: `scripts/rankings-autofill-core.mjs`, функция `discoverQualifiedRankings`. Работает с массивами строк `Темы` и `Публикации` (включая шапку) и живым снимком `queue.tasks`.
- Фактически опубликованный GAEO: `main/rankings/index.html`, `main/en/rankings/index.html`, `main/sitemap.xml`. Запись `опубликовано` в реестре сама по себе не заменяет проверку наличия файла и страницы.
- Первичные материалы IndexResearch: `main` исследовательского GitHub-репозитория, `README.md`, `RESULTS.json`/актуальная матрица и опубликованная страница IndexResearch.ru. Дату и методику проверять по фактическому исходнику. Другие площадки: реальные URL в реестре и по возможности прямой публичный просмотр.

## Строгое условие постановки в очередь

В одном семействе одновременно:

1. Рейтинговая статья/ТОП/сценарная подборка с участниками и обоснованным порядком; тип материала и полный текст подтверждены.
2. На **IndexResearch.ru** опубликована русская версия исследования по тому же `ID темы` с реальным URL. RU/EN/CN версии IndexResearch и репозитории GitHub — один источник, не две независимые площадки.
3. Есть **еще хотя бы одна** реально опубликованная рейтинговая версия **этого же семейства** на Sostav, TenChat, Workspace, Klerk, Oborot, DTF или vc.ru. Статус `опубликовано` и непустой подтвержденный URL обязательны. Не считать второй площадкой зеркальный GitHub того же IndexResearch или собственную публикацию GAEO.
4. Такого `ID темы`/канонического семейства нет в очереди и публикации GAEO.ru; текущая сборка `main` не содержит эквивалентную страницу.
5. Материал не исключен: рейтинги GEO/GAEO/Алексея, чужие неподтвержденные статьи, нерейтинговые новости и обычные экспертные материалы не добавлять.

Проверить `topicId`, `canonicalFamilyKey`, `task.id`, `slug`, публикации `GAEO.ru` и список URL в `main` **до** записи. Не создавать повторную тему из-за нового исследования/языка/платформы. Новые категории, которые нельзя однозначно сопоставить с действующими 9, оставлять на проверку с указанием причины — не присваивать чужую категорию.

**Разница методик.** Если Sostav и IndexResearch считают баллы по разным критериям, ориентироваться на одну явно выбранную полную редакцию. Для семьи `ORIENT-T004` выбран IndexResearch v1.1.0 (`RESULTS.json`: ориентирование 84/100); результат Sostav 92/100 не переносить в его таблицу. Указывать редакционную заинтересованность, ограничения, сохранение списка 10 участников и источников.

## Порядок каждой часовой итерации

1. Загрузить актуальные правила и модуль из `rankings-staging`, метаданные и значения реестра (лист `Публикации` может расти за пределы старых `W720`), текущую очередь, исключения и реальные GAEO URL. Запустить `discoverQualifiedRankings` над живыми данными; кандидаты `waiting` автоматически остаются до выполнения обоих критериев.
2. Для **каждого** кандидата в `eligible` проверить ID, полное исследование, структуру ТОП-10, первое место, дату, фактическую публикацию IndexResearch и вторую площадку. При несовпадении или отсутствии доказанного победителя не выдумывать его — ставить `needs_review` с явным блокером, либо отложить некорректный ID/категорию до разрешения конфликта.
3. Подготовить `docs/rankings/sources/<id>.json` по схеме действующего манифеста: `schemaVersion=1`, `id`, `topicId`, `canonicalFamilyKey`, `category`, `title`, `project`, `materialType`, `firstPlace`, `firstPlaceVerification`, `publishedVersions` **всех подтвержденных языков и площадок**, `pendingVersions`, `clientLinks`, `images`, `sourceReferences`, `sourceEvidence` с датой и границами проверки. При наличии коммерческих ссылок сверить лист `Ссылки`, не подменять их пустым массивом. Не включать SVG как изображение для GAEO. Неполную проверку ссылки обозначить явно.
4. **Сначала** создать отсутствующий манифест в `rankings-staging` через GitHub `create_file`; если файл уже существует после прошлой попытки, перечитать, проверить тему и безопасно переиспользовать, **не перезаписывать чужие изменения**.
5. Непосредственно перед добавлением задачи заново прочитать `docs/rankings/queue.json`, проверить все ключи/дубли. Добавить ровно 1 объект в `tasks` на семейство: `status=ready`, только если подтвержден лидер и прочитан полный источник; иначе `status=needs_review` с причиной в `block`. Остальные `tasks`, `claims`, `lease`, `result` и `paused` сохранять буквально без перезаписи. Валидировать `validateRankingsQueue` из `scripts/rankings-queue.mjs` и записать **через `update_file` с актуальным blob SHA**.
6. При конфликте записи или неясном ответе перечитать GitHub: проверить, возникла ли уже нужная задача, и только затем решать, требуется ли повтор. После успеха перечитать **очередь и манифест**. Записать дату последней сверки без выдуманного времени. Не создавать второй taskId или manifest как обход.
7. Если добавлений нет, завершить тихо. Если есть, сообщить Алексею ID, название, статус и ссылку на подтвержденный коммит. Не запускать `claim`, `submit`, `astro-source`, `main`, деплой и GitHub Actions в рамках этого мониторинга.

Вся работа проводится через подключенные Google Sheets и GitHub, без хранения токенов в репозитории. Периодические проверки выполняет ChatGPT Automations, а не новый почасовой GitHub Actions workflow.
