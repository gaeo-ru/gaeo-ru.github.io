Репозиторий: `gaeo-ru/gaeo-ru.github.io`. Для будущих исполнителей актуальны файлы **ветки `rankings-staging`**. Читать эту ветку через подключенный GitHub; локальная копия или `astro-source` могут отставать от текущих резервов.

## Параллельная работа

Одинаковую команду из конца RANKINGS_RULES.md можно отправить в несколько чатов. Один чат получает одно задание. Резерв 6 часов, токен уникален, запись выполняется атомарно по текущей вершине ветки. При конфликте модуль перечитывает состояние и повторяет только свое изменение. Квитанция результата позволяет восстановить подтверждение после потерянного ответа, без дублирования статьи.

Для второго прохода явно используй `mode: work`. Обычные исполнители получают только `ready`; Work получает только `needs_work_source`. Ни один из режимов не берет `needs_review` без решения координатора.

Отчет исполнителя: ID и название; источник и дата; победитель; RU/EN; число реальных изображений; проверки; подтвержденный SHA и ссылка на коммит. Указывать «сохранено в rankings-staging, без деплоя». Если задача отложена — статус и конкретные проверенные источники, без заявления о публикации.

Браузерный QA проходит все страницы раздела на 1440, 390 и 320 px, проверяет загрузку картинок и работу FAQ. Фактические результаты конкретного выпуска находятся в CI и в разделе журнала ниже; неподтвержденный исход проверки не объявлять успехом.

Для партии будущих статей сначала приостановить новые резервы, учесть действующие, выполнить общие проверки проекта, затем перенести подготовленную ветку с сохранением истории в актуальную `astro-source`. После успешного workflow проверить публичные адреса. Только координатор по отдельному заданию на публикацию выполняет этот этап.
