## Где продолжать

Репозиторий: `gaeo-ru/gaeo-ru.github.io`. Для будущих исполнителей актуальны файлы **ветки `rankings-staging`**. Читать эту ветку через подключенный GitHub; локальная копия или `astro-source` могут отставать от текущих резервов.

- [RANKINGS_RULES.md](RANKINGS_RULES.md): редакция, структура, SEO/GEO, schema.org, источники, иллюстрации и ссылки.
- [RANKINGS_WORKER.md](RANKINGS_WORKER.md): точный протокол обычного чата, резерв, восстановление, изображения, один коммит.
- [RANKINGS_YANDEX_SOURCES.md](RANKINGS_YANDEX_SOURCES.md): действующий API-доступ к Яндекс.Диску.
- [Очередь](rankings/queue.json): единственный источник статусов и резервов.
- [Инвентарь](rankings/inventory.json): объединенные семейства и ссылка на манифест каждого.
- [Исключения](rankings/excluded.json): GEO/GAEO, сторонние и нерейтинговые материалы.
- [Проверки Яндекс.Диска](rankings/yandex-sources.json): фактические пути и ссылки на результаты API.

`astro-source` автоматически публикует сайт. `main` — сгенерированная production-версия. Будущий чат не пишет ни в одну из этих веток, не запускает Actions/Pages, не создает и не сливает PR для обхода этого ограничения.

`committed` означает сохранение результата в staging. Фактический выпуск подтверждается отдельно по `result.releaseStatus`, опубликованной ветке и публичному сайту.

## Структура раздела

Канонический файл статьи: `src/data/rankings/articles/<id>.json` (RU и EN). Изображения: `public/assets/rankings/<id>/`. Структуру данных проверять по актуальному валидатору и файлам, не по старым образцам.

`scripts/generate-ranking-pages.mjs` собирает индексы и рубрики, `src/lib/rankings.mjs` проверяет данные и генерирует schema.org, `public/assets/rankings.css` задает стиль. Исполнитель не коммитит генерируемые HTML.

На 14.11.2026 рубрик **9**: Товары, Туризм, WMS, Фулфилменты, Брендинг, Ускорение сайтов, Частные SEO-специалисты, Спортивное ориентирование, Культурное образование. В исходном модуле очереди было 8, новая рубрика SEO добавлена позже. Сверять рубрики с `main`.

## Параллельная работа

Одинаковую команду из конца RANKINGS_RULES.md можно отправить в несколько чатов. Один чат получает одно задание. Резерв 6 часов, токен уникален, запись выполняется атомарно по текущей вершине ветки. При конфликте модуль перечитывает состояние и повторяет только свое изменение. Квитанция результата позволяет восстановить подтверждение после потерянного ответа, без дублирования статьи.

Для второго прохода явно используй `mode: work`. Обычные исполнители получают только `ready`; Work получает только `needs_work_source`. Ни один из режимов не берет `needs_review` без решения координатора.

Отчет исполнителя: ID и название; источник и дата; победитель; RU/EN; число реальных изображений; проверки; подтвержденный SHA и ссылка на коммит. Указывать «сохранено в rankings-staging, без деплоя». Если задача отложена — статус и конкретные проверенные источники, без заявления о публикации.
