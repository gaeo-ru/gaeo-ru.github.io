## Чтение в обычном чате

1. Прочитать актуальный README моста.
2. Создать уникальный ID длиной 3–80, латиница, цифры, дефис и нижнее подчеркивание. Для нового запроса новый ID.
3. Через GitHub `create_file` записать JSON в `main:requests/<id>.json`.
4. Подождать штатный workflow, прочитать `main:results/<id>.json`. Если результат еще 404, проверить существующий запуск; это не отсутствие файла на Диске.
5. Проверить `status`, `truncated`, `complete`, `next_offset`, `total`, `offset` и фактическое содержимое. Не путать успешный workflow с полнотой извлечения.

Пример листинга (ID в примере заменить):
```json
{"id":"unique-id","action":"list","account":"main","path":"/!GAEO/Статьи","limit":1000,"offset":0}
```

Для файла `read`:
```json
{"id":"another-unique-id","action":"read","account":"main","path":"<точный путь из листинга>","max_characters":100000}
```

Для поиска, когда неизвестна папка:
```json
{"id":"another-unique-id","action":"search","account":"main","query":"<фрагмент имени>","limit":100,"max_scanned":20000,"offset":0}
```

`search` ищет **по именам файлов**, не по тексту и не по именам папок. Продолжать по `next_offset` до `complete:true`; пустой частичный ответ не доказывает отсутствия. Для папок использовать `list` с пагинацией до `total`.

Для XLSX: `inspect_xlsx` принимает `path` и `needles` (до 20 строк), без needles возвращает только первые 140 непустых ячеек. Общий `read` извлекает ограниченный текст. `download_base64` подходит для оригинальных небольших файлов до 750 КБ; не выводить base64 в чат или контекст. `read` ограничен 16 МиБ и 100000 символов.

## Правила именно этой очереди

- Читаем нужные публикационные исходники; не меняем файлы Диска.
- Сначала Google Drive и Яндекс.Диск. Если текст найден хотя бы в одном, обычный чат может подготовить статью.
- Если отсутствует только изображение, публикуем без него, без генерации.
- Если полноценный текстовый исходник не найден в обоих хранилищах после завершенных поисков, фиксируем в очереди `needs_work_source` с конкретными проверенными папками/запросами и ссылкой на опубликованную версию. Обычный чат ее не переписывает с внешнего сайта.
- Ошибку доступа, незавершенный поиск и усеченный `read` отмечаем как отдельное ограничение, а не как «исходника нет».
- Не публикуем приватные документы, секреты, временные download URL и служебные реестры. В публичную статью идет только разрешенный опубликованный материал и проверенные клиентские/версионные ссылки.
